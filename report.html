How this is measured
  1. The tasks. Each is a real change from this project's history that held a bug, fixed in a later commit. The model reviews the change by reading the code as it was then. It cannot see what came after.
  2. Found or missed. A fresh model session judges each review without knowing which model wrote it. A bug is found only when the review names that wrong behaviour.
  3. Other bugs the reviews found. Every finding is checked against the code. One that is real (the wrong behaviour can be shown from the code) and serious (a wrong result, lost data, a crash, a hang or a security hole in ordinary use) is added as one more bug, and every model is judged on it.
  4. Small findings. Real but small findings, such as style, documentation, tests and rare corners, are counted beside each model and never change the score. A model cannot win by being picky.
  5. Time and cost. Time is the model's own working time, added over all reviews. Cost is what those tokens would cost at the vendor's API prices; on a subscription the same run uses plan quota instead and costs no extra money.
